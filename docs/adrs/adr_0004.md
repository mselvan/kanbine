# ADR-0004: Adopt DDD-Aligned Microservices via Strangler Migration

## Status
Accepted (architecture direction)

## Context
Kanbine currently runs as a single Spring Boot monolith. The code has clear functional seams (auth/users, assignments, timecards), but service boundaries, data ownership, and operations are coupled into one deployable. For production-grade scale, reliability, and team autonomy, the system needs bounded contexts with independent deployment and runtime controls.

## Decision
We will migrate from the monolith to DDD-aligned microservices using an incremental strangler approach.

### Target Bounded Contexts / Services
1. `identity-access-service`
2. `assignment-service`
3. `time-tracking-service`
4. `reporting-service` (read model, phase-later)

### Architecture Guardrails
- Per-service database ownership; no cross-service table writes.
- API and event contracts for cross-context communication.
- API Gateway as ingress for external consumers.
- Centralized observability, security policy, and CI/CD quality gates.
- Incremental cutover with rollback support for each phase.

## Consequences

### Positive
- Improved deployability and reduced blast radius.
- Better domain alignment and clearer ownership boundaries.
- Stronger production operations through standardized platform controls.

### Negative
- Higher operational complexity (networking, deployments, monitoring).
- Additional engineering effort for contracts, migration, and platform setup.
- Temporary coexistence complexity while monolith and services run in parallel.
